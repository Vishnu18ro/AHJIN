# AHJIN 2.0 — Canonical Domain Contracts

## 1. Core Contracts Summary

| Contract | Purpose | Domain Location |
|---|---|---|
| `TaskRequest` | Canonical input from Interface | Core Boundary |
| `UserIntent` | Primary text & attachments | TaskRequest |
| `TaskContext` | Conversation history & session ID | TaskRequest |
| `ExecutionPlan` | Cognitive plan generated by BERU | BERU ──► Harness |
| `PlanStep` | Single unit of execution | ExecutionPlan |
| `ModelStepIntent` | Model instruction & capability needs | PlanStep Payload |
| `CapabilityRequirements` | Provider-agnostic model needs | ModelStepIntent |
| `ContextualizedPrompt` | Assembled prompt for model | Harness Internal |
| `ModelInvocationResponse` | Canonical provider response | Provider ──► Harness |
| `TaskResult` | Final result returned to user | Harness ──► Core ──► Interface |
| `AhjinError` | Canonical error model | System-Wide |

## 2. Architecturally Reserved Type Stubs (Future)

Defined as typed interfaces now to establish clean entry points:
- `MemoryContext`: Typed stub for memory retrieval.
- `RetrievalContext`: Typed stub for RAG document retrieval.
- `ToolInvocationRequest` / `ToolInvocationResult`: Typed stubs for tool execution.
- `AgentStepPayload`: Typed stub for agent invocation.
- `VerificationStepPayload`: Typed stub for verification step.

## 3. Forbidden Contract Fields

Canonical domain contracts MUST NOT contain:
- Interface-specific IDs (`telegram_chat_id`, `telegram_update_id`).
- Provider-specific payloads or SDK objects (NVIDIA JSON structures).
- HTTP status codes or raw Python exception stack traces.
- Raw API keys, tokens, or credentials.
